## Overview

Intelligent textbooks are usually generated by cloud-hosted frontier models.
This book asks whether one NVIDIA DGX system, running an open-weight small
language model, can generate the same kind of interactive textbook from start
to finish without sending a token to the cloud.

It teaches how to answer that question with measurements instead of opinions.
Readers reach the machine, verify its hardware with Python probes, choose and
serve a model, run the textbook-generation skills against it, and score what
comes out. Every step ends with a test, so a failure is caught where it
happens and not three layers later. The book keeps three terms separate
throughout: **cost** is what you pay to own and operate hardware, **price** is
what a provider charges for a service, and **quality** is how good the
generated textbook is.

The book is written for AI and machine-learning engineers, instructional
technologists, technical authors, and IT infrastructure leads who must decide
whether a local DGX can replace or supplement cloud AI services. It assumes a
comfortable command line, basic Python, and basic git. It does not assume any
GPU administration or model-serving experience.

Because the raw material of an evaluation is not safe to share, the book also
teaches how to sanitize probe reports, logs, and screenshots before anything is
published. This repository is public, and it contains no addresses, hostnames,
credentials, or logs from the machine under test.

## Where the Evaluation Stands

The benchmark asks each model to write an Algebra I textbook in three stages: a
learning graph, a chapter structure, and the chapter text. The book is a work in
progress. Every test has run once, no person has yet judged whether the
generated content is correct, and no cloud-generated baseline exists yet. See
[Model Results](https://dmccreary.github.io/dgx-eval/models/) for what each
model produced and
[Evaluation Status](https://dmccreary.github.io/dgx-eval/appendices/evaluation-status/)
for the stages each one has finished.

## Getting Started

### Clone the Repository

```bash
git clone https://github.com/dmccreary/dgx-eval.git
cd dgx-eval
```

### Install Dependencies

This project uses MkDocs with the Material theme. Math is rendered in the
browser with KaTeX, which the site loads from a CDN, so there is nothing else
to install for the site itself.

```bash
pip install mkdocs mkdocs-material
```

### Build and Serve Locally

Build the site. The `--strict` flag turns broken navigation links and missing
files into errors:

```bash
mkdocs build --strict
```

Serve locally with live reload:

```bash
mkdocs serve
```

Open your browser to `http://127.0.0.1:8000/dgx-eval/`.

### Deploy to GitHub Pages

```bash
mkdocs gh-deploy
```

This builds the site and pushes it to the `gh-pages` branch.

### Using the Book

**Navigation:**

- Use the left sidebar to browse the 23 chapters, each with a quiz and
  annotated references
- Use the search box to search all content
- The [Glossary](https://dmccreary.github.io/dgx-eval/glossary/) and
  [FAQ](https://dmccreary.github.io/dgx-eval/faq/) cover the terms and common
  questions

**Interactive MicroSims:**

- Found under `docs/sims/`, one directory per simulation
- Each runs standalone in the browser, and most are built with p5.js
- A colored dot in the left navigation shows a MicroSim's status, such as
  scaffold, built, or approved

**Running the evaluation yourself:**

- Start with the
  [Getting Started appendix](https://dmccreary.github.io/dgx-eval/appendices/getting-started/)
- The Python and shell code lives in `src/`; see [src/README.md](src/README.md)
- The benchmark's fixed input lives in `benchmark/`

## Security

The DGX being evaluated is a real machine, and this repository and its site are
public. Nothing in the repo may make that machine easier to find, reach, or log
in to. Examples use placeholders such as `<dgx-host>`, `<user>`, and
`<tailnet-name>.ts.net`, and captured output is sanitized by hand before it goes
into a chapter. Raw logs are kept out of the repository (`*.log` is
gitignored). If you spot anything that looks like a real address, hostname,
credential, or log excerpt, please report it through the issue tracker without
repeating the value in the report.
