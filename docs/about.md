# About

## A Primer for Every Child

In Neal Stephenson's novel *The Diamond Age*, a girl named Nell is given a book
unlike any other: *A Young Lady's Illustrated Primer*. It does not teach a
fixed course. It pays attention to Nell, works out what she needs next, and
tells her stories built from her own life, at the moment she is ready for
them. It changes the course of her life.

For three decades the Primer was a fantasy. Language models have made it an
engineering problem. A model can now write a lesson, build an example around a
child's own interests, and answer the follow-up question. The hard part has
moved. It is no longer only whether a machine can write the page. It is what a
whole book costs to produce, and who can afford to produce it.

## The Whole Game Is Cost

If every intelligent textbook needs a cloud subscription, a team, and weeks of
editing, the children who most need a Primer are the last to get one. If a
book can be generated by an open-weight model running on one machine you own,
with no token sent to the cloud, the arithmetic changes. A Primer for every
child on earth needs a book to cost close to the electricity it takes to write
it.

This book is about that arithmetic. It takes one NVIDIA DGX, a small language
model, and the course description of a real course, Algebra I, and measures
what it takes to turn the description into a textbook. Each strategy for
lowering the cost is something you learn to do and to measure:

| Strategy | Why it lowers the cost | Where you learn it |
|---|---|---|
| Own the hardware instead of renting tokens | The cost is fixed and spread over every book, not charged per token on each one | [Chapter 4](chapters/04-local-versus-cloud/index.md), [Chapter 6](chapters/06-cost-price-quality/index.md) |
| Use a small open-weight model | A model that fits in memory runs fast on a single machine | [Chapter 3](chapters/03-small-language-models/index.md), [Chapter 14](chapters/14-candidate-models/index.md) |
| Size and tune before you generate | A model that does not fit, or a context that is too long, wastes hours before it fails | [Chapter 11](chapters/11-model-sizing-and-fit/index.md), [Chapter 15](chapters/15-optimizing-performance/index.md) |
| Build top down, with a test at every step | A failure is caught where it happens and not three layers later | [Chapter 1](chapters/01-intro-intelligent-textbooks/index.md), [Chapter 2](chapters/02-learning-graphs-microsims-rules/index.md) |
| Run unattended, in a container | A harness that works with nobody watching turns machine time into books | [Chapter 16](chapters/16-agent-loop-and-tools/index.md), [Chapter 18](chapters/18-containing-the-harness/index.md) |
| Report the cost per textbook | You cannot lower a cost you cannot see | [Chapter 21](chapters/21-running-the-benchmark/index.md), [Chapter 22](chapters/22-diagnosis-and-reporting/index.md) |

The [Cost Analysis](appendices/cost-analysis.md) appendix turns the last row
into a model you can adjust: hardware, setup time, electricity, and the hours
one book takes.

## The Event Stream Is the Point

A textbook is not intelligent because it has animations. It is intelligent
because what the reader does with it leaves a record. Each answer a student
commits to, and each control they move, is an event. The stream of events is
the raw material for predicting whether that student has mastered a concept. A
Primer can adapt only to a child it can see, and the event stream is how it
sees.

That is why interactivity is a requirement in this book and not a garnish.
Every MicroSim specification states an **Evidence of Mastery**, the pattern of
events that counts as proof, such as 5 of 6 answers correct, each committed
before the simulation reveals the right one.

!!! mascot-thinking "Exploration Is Not Evidence"

    ![Tera thinking](img/mascot/thinking.png){ class="mascot-admonition-img" }
    Each specification separates the two, with a line such as "Inspecting the
    graph before answering is exploration, not evidence." Dragging a control
    shows what a learner did, and an answer committed before the reveal shows
    what they know. Only the second belongs in the stream that predicts mastery.

On the [five levels of intelligent textbooks](sims/book-levels/index.md), this
is the step from Level 2 to Level 3: a book that only offers quizzes becomes a
book that reads what the quizzes record. Level 5, lessons generated in real
time for each reader, is the Primer.

## Why This Book Stops at the Fourth Tier

[Chapter 1](chapters/01-intro-intelligent-textbooks/index.md#five-tiers-from-one-document-to-a-whole-book)
describes the generation pipeline as five tiers, each built from the tiers
above it. This book evaluates the first four.

| Tier | Component | Made by | In the benchmark |
|---|---|---|---|
| 1 | Course description | A person | The fixed input |
| 2 | Learning graph | The model | Stage 1 |
| 3 | Book structure | The model | Stage 2 |
| 4 | Chapter content, including a specification for every MicroSim | The model | Stage 3 |
| 5 | Working MicroSims, glossary, FAQ, and quizzes | A model, outside this benchmark | Not tested |

Small language models are not yet strong enough to write high-quality
MicroSims, so the benchmark does not ask them to. That is not a retreat,
because the first four tiers hold everything the event stream depends on:

- The **learning graph** says which concept an event belongs to and which
  concepts must be mastered first, so a failure can be read against what the
  student already knows.
- The **book structure** fixes the order, so no concept is tested before its
  prerequisites are taught.
- The **chapter content** specifies what every interaction must elicit and
  what counts as evidence.

A stronger model or a person can build working MicroSims from those
specifications later, and the boundary moves outward as small models improve.
The method in this book is how you watch it move.

## What You Will Be Able to Do

After the last chapter you will be able to:

- Reach a DGX over a private network and verify what it has with Python probes
- Predict whether a model fits in memory before you download it
- Serve an open-weight model locally and run textbook-generation skills
  against it from a sandboxed harness
- Score what comes out with objective measures, and diagnose why a run failed
- Report the cost per textbook and the break-even point against cloud pricing
- Publish the results without making the machine easier to find or reach

## An Honest Scoreboard

This book does not claim the problem is solved. As of October 10, 2026, ten
open-weight models had been tried on the first three stages. Six produced a
learning graph, and two wrote every chapter they had designed. No person has
yet judged whether the content teaches well, and no cloud-generated baseline
exists to compare against.

[Evaluation Status](appendices/evaluation-status.md) tracks every model, and
[Model Results](models/index.md) shows exactly what each one wrote. A method
that reports a failed run as data is worth more than a demo that shows only the
success.

## Audience

AI and machine-learning engineers, instructional technologists, technical
authors, and IT infrastructure leads who must decide whether a local DGX can
replace or supplement cloud AI services for generating textbooks. It is also
for anyone who believes the cost of a book, not the idea of one, is what keeps
a Primer from every child.

You need comfort with a Linux or macOS command line, basic Python, basic git
and GitHub, and hands-on experience with at least one generative AI assistant.
No experience with GPU administration, model serving, or model training is
required. The [course description](course-description.md) lists the learning
outcomes.

## How to Use This Book

- Read chapters in order — concepts are introduced in dependency order.
- Use the search bar (top right) to jump to a specific term.
- Try the MicroSims as you encounter them; they are the fastest way to build
  intuition for a new concept.
- Check the [Learning Graph](learning-graph/index.md) when you want to see how
  a concept fits into the larger picture.
